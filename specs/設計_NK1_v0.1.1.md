## 0. 結論

1. NK1 是**一條生成管線**，不是平台：解析 → 模板規格 → 檢索 → 受 schema 約束的生成 → 數值掃描 → 錨點式引用驗證 → 內容包（＋丟棄式 docx）→ 稽核日誌。七段，每段可單獨測、可單獨換。
2. **T 層的模板不是 docx，是規格**：從 116 段三顧人員手寫的 prompt 抽出的「章節／欄位／格式」結構化 schema（`T-spec`），14 份表格型受控文件當表單地基，22 份 pdf 中經來源確認為公開法規／指引者（依檔名目前僅 6 份）當引用語料。
3. **引用驗證器 D1 是地基中的地基**，先於任何生成功能做，**由 NK1 先建 v1**，NK-Locus 日後採用同一支；生成功能不通過 D1 的輸出一律標「無依據」，不丟、不補。
4. **檢索段＝自建薄管線：每 scope 獨立 SQLite FTS5（v1 無向量段；向量段留 v2，屆時同為每 scope 獨立檔，見薄管線 v0.2 §0.2），隔離在檔案邊界、不在 WHERE 條件。** WeKnora 只作參照（W0-W 2026-09-20：隔離為查詢層過濾、跨租戶旗標可開、Langfuse 預設雲端主機、無 digest 釘選）。
5. 四道閘（A5／G1／T 層核定／合約閘）擋 W1 動工，不擋本設計。但本設計凡依賴閘後資料處，標 ⛔。

## 1. 產品定義與不做清單

**一句話**：NK1 讀客戶自己的文件（C 層）＋三顧的模板規格與語料（T 層），依三顧 QA 定義的文件結構，生成「能走進客戶文件管制流程的草稿」，每一句主張**標示出處狀態**（supported／partial／unsupported／uncited）。

**不做**（凡做了就是重做 NK-Locus 或太陽）：版面與受控格式、簽核、文件編號分配、版次管理、法規符合性最終判定、風險等級最終判定、任何「GMP 等級」承諾。過渡期 docx 是例外，見 §6.3。

## 3. 三段架構中的位置

[NK1 生成] ──內容包──▶ [NK-Locus 管理：版面／隔離／交叉引用／簽核，零 LLM] ──▶ [太陽：法規審] ──▶ 人簽
NK-Locus → NK1：scope id、文件登錄表（格式由 NK-Locus 規格定義；過渡期 NK1 自持實例）；驗證器 CLI（NK1 先建 v1，兩線共用同一支）。

介面只有三個物件：**內容包**（NK1→NK-Locus）、**scope id 與文件登錄表**（格式歸 NK-Locus 規格）、**驗證器 CLI**（同一支碼）。此外零耦合。四處介面修改待阿析回（第④步）；**「驗證器由 NK1 先建」是介面對齊第一項，要讓阿析知道。**

## 4. 資料模型

### 4.1 T 層（三顧資產，跨客戶共用，經 §4.4 資料包出門到客戶機器）

| 物件 | 來源 | 形式 | 閘 |
|---|---|---|---|
| `T-spec`（模板規格） | 116 段 prompt，**每份文件題目一份（116 份）**，類別層只做索引 | YAML schema：`doc_type／kind(section|form)／sections[]／fields[]／instruction_kinds[]`；**只含結構，不含任何原 prompt 句子** | 可外用（輕）：候選詞表過遮蔽閘＋三顧 QA 過目 |
| `T-form`（表單地基） | 14 份表格型受控文件 | 表格骨架（欄名、列名、佈位符），內容清空 | T 層核定（逐份）⛔ |
| `T-ref`（法規語料） | 22 份 pdf 中經來源確認為公開法規／指引者 | 條文級切分，每條有 `ref_id／version／clause／text_norm` | 來源清單（三顧 QA 補） |
| `T-style` | 三顧文件編號格式、用語表 | 正規表達式＋詞表 | 無 |
| `T-feedback`（候選） | 2 份【審閱意見回饋】 | 三顧 QA 對 NK 輸出的否決紀錄 | 等核定；列入候選 |

**T-spec 抽取分兩階**：(a) 純腳本抽候選詞表（章節候選、欄位候選、指令類型計數），阿K 只看統計與去重詞表——已完成（2026-09-20，418／190／6 列）；(b) 詞表過遮蔽閘後**由三顧 QA（人）或本地模型**整理成 schema。阿K 不讀任何一段 prompt 全文；nk1-guard 第 5 道擋 T-spec 與 prompt 的 ≥30 連續相同字元。

### 4.2 C 層（客戶資產，逐客戶隔離，永不出客戶機器）

URS／RA／FDS／QRA 等，解析成條文級知識庫：`doc_id／version／status／clause_id／text_norm／scope`。版本來自文件登錄表（D5）：每次生成前比對，作廢版拒引。過渡期登錄表為 NK1 自持 `registry.csv`（編號／版次／狀態，人工餵）。

### 4.3 隔離（D4，ISO-02／03）— 檔案邊界

**每 scope 一個目錄，內容以薄管線 v0.2 §1 為準（v1 無向量段）。** 不存在跨 scope 的表或索引；**生成程序只看得到自己的 scope 目錄；scope 由連線目標決定，不由參數決定**（薄管線 v0.2）；程式上沒有「列出所有 scope 再過濾」的路徑。生成紀錄寫 scope id。scope id 格式照 NK-Locus 規格；過渡期 NK1 自持 `scope.yaml`。

### 4.4 T 層資料包（三顧→客戶機器的唯一通道）

- 建置於 Air2 本機腳本：`T-spec／T-form／T-ref／T-style` 打包為 tar，age 加密，產生 `manifest.yaml`（檔名／sha256／版次／核定人職位／建置時間）。
- **manifest 進 repo，內容永不進 repo。**
- 交付與更新走人力介質（隨部署或維護到場）；安裝時比對 manifest，任一 hash 不符即拒裝。
- 執行期零回連：更新只能靠下一次人力交付。

## 5. 生成管線（七段）

| 段 | 做什麼 | 輸入→輸出 | 可換件 |
|---|---|---|---|
| ① 解析 | 客戶文件→條文級結構 | docx／pdf→C 層 KB | docling 候選（本地） |
| ② 選規格 | 依 `doc_type` 取 `T-spec`；**`kind == form` 時另取 `T-form`** | 類別→schema | 無 |
| ③ 檢索 | **薄管線**：對該 scope 的 `c.sqlite`（FTS5 n-gram，見薄管線 v0.2 §2）與 `T-ref` 取候選條文，回 `ref_id／clause／offset` | schema→候選集 | v1 無（向量段留 v2，屆時向量庫可換） |
| ④ 生成 | 本地模型，受 schema 硬約束（instructor 類），每主張輸出「錨點 3–8 字＋ref_id」而非引句 | 候選集→草稿 JSON | 模型可換 |
| ⑤ 數值掃描（D3） | **只掃 `body`**：regex 掃數字＋單位，命中即退回重生；白名單只放條號／章節號／日期格式。數值只准出現在已驗證的 `quote` 裡 | 草稿→草稿或退回 | 無 |
| ⑥ 引用驗證（D1／D2） | 錨點在 `text_norm` 定位→回填 offset 與整句 `quote`；找不到→`unsupported`；模型未給 ref→`uncited`。保留主張、標狀態 | 草稿→已驗草稿 | 共用 CLI |
| ⑦ 輸出 | 內容包（正式）＋丟棄式 docx（過渡）＋稽核日誌 | 已驗草稿→三檔 | 無 |

**④ 的關鍵設計**：模型不給引句、不給 offset，只給錨點；驗證器回填。trust-but-anchor 的實測是逐字引句 64–73% 對，錨點法 91–100%。

## 6. 輸出

### 6.1 內容包 v0.1（正式輸出，唯一）

pack:
  pack_id, scope_id, doc_type(T-spec id), generated_at
  origin: "NK1/<版本>"            # P5 必填不可關閉
  disclosure: "AI 草稿，須經修訂、審核、簽核"   # P5 必填不可關閉
  model: {name, version, host: "local"}
  validator_version                # D2
  kb_snapshot: {C: hash, T: manifest hash}
  sections[]:
    section_id (來自 T-spec)
    body: 佈位化文字，數值一律 {field_id}   # D3
    claims[]:
      text, refs[]: {kind, id, version, clause, anchor, offset, quote, status: supported|partial|unsupported}
      status: cited|uncited
  risks[]: {…, level, status: "proposed"}   # D7
  issues[]: URS 與法規不一致項，只記不判   # D8
  fields[]: {field_id, type, unit?, source_hint}
  translation?: {lang: en, origin: "generator-translation"}   # D6

### 6.2 稽核日誌（生成端最低限度）

`who／when／scope／doc hashes／T-spec id／model／validator_version／pack_id`。append-only，歸樂迦。過渡期 `who` 來自 NK1 自持最小帳號表（本機、樂迦 QA 維護），G2 定案後移交。

### 6.3 丟棄式 docx（過渡期）

檔頭固定「草稿・非受控文件」；無簽核欄、無文件編號、無版次；**docProps 寫 `creator＝NK1/<版本>`、`created＝真時間`**。NK-Locus 能收件即刪此段。

## 7. 引用驗證器（D1／D2）規格

- **由 NK1 先建 v1**；NK-Locus 日後採用同一支，版本號進內容包。
- 輸入：claims[].refs 與 KB 快照。輸出：每 ref 的 status 與回填欄位、覆蓋率報告。
- 定位三級：exact → normalized → fuzzy（閾值可調）；fuzzy 命中只給 `partial`。
- 零依賴、可攜 CLI（sourcecheck 形狀）。
- **驗收**：植入 10 條錯引（假 ref_id、改寫條文、版本錯）全判 unsupported／partial；覆蓋率報告可重現。
- **負例候選**：87 份 NK 輸出中的文件編號（XXX-XX-999 82 次／23 份、地基僅 2 份）——⛔ 合約閘＋先做編號對地基與三顧編號體系的比對，證實為自編者才入負例集。

## 8. 部署形態與硬體

- 單機、容器化、全離線；模型本地（Ollama 或 vLLM，依硬體）。
- **安裝期**：離線 image tar＋digest；**執行期**：零對外連線（含遙測、更新檢查）。
- **硬體未定**（Alex 一句話：現成主機／採購／先小模型驗證）；薄管線後硬體需求主要在模型，不在檢索。
- **樂迦有沒有能跑本地模型的主機**——硬體那句話一起答。

## 9. 安全與反面約束（對照 NK-Locus v0.2 §11 與 W0-W 所見）

| 反面 | NK1 驗收 |
|---|---|

## 10. 可證偽驗收（J-xx，進 predictions.md）

- J-01 離線環境（拔網）完成一次完整生成。
- J-02 植入 10 條錯引全數不通過驗證器。
- J-03 生成 20 份草稿抽驗，數值漏網 0 件；任一漏網即 fail。
- J-04 兩個 scope 交叉：A 的生成結果零 B 的 ref_id；且檔案系統上 A 的程序無法開啟 B 的目錄。
- J-05 內容包通過共用驗證器（同版）零 schema 錯。
- J-06 `origin／disclosure` 欄位無法透過任何設定關閉。
