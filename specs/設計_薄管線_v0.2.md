# 設計 2026-09-20 — NK1 檢索段薄管線 v0.2（定版）

> 起草：阿觀　審：阿K 唯讀意見（C1–C7、E1–E4、D1–D5、意見 1–8、Q1–Q3）　裁：Alex「採 n-gram 當 v1 主線；其餘七項照改」
> 取代 v0.1／v0.1.1。落地：阿K → `specs/設計_薄管線_v0.2.md`；連帶改驗證器契約 v1.1 與設計包 §4.3 措辭。
> 鐵律：隔離由 OS 強制，不靠程式紀律。判準：不是 kernel 擋的，就別叫它物理隔離；不是 root 設的，就別叫它 append-only。

## 0. 結論

1. 一 scope＝一目錄＋一常駐程序＋一 OS user；跨 scope 開檔由 kernel 拒絕。呼叫端經該 scope 的 unix socket 連線，socket 檔在 scope 目錄內、700——連得上就是選對了 scope，沒有 scope 參數。
2. 檢索 v1＝FTS5 unicode61 tokenizer＋**ingest 端自切 bigram＋trigram** 寫入索引欄；bm25 排序。無向量段（設計保留於 v2，J-08 觸發）。
3. 對外一個模組 `nk1_retrieve`；`export_kb()` 產物**逐欄對齊驗證器契約 v1.1**（含 `clause`、`status`）；共用 `nk1_normalize`，`normalize_version` 進 meta，不符拒 search。
4. T 層一組同形檔，唯讀、跨 scope 共用、來自資料包。
5. 不做：WeKnora 任何元件、跨 scope 共用索引、呼叫端傳 scope 參數、mode 參數、查詢日誌含正文。

## 1. 目錄、權限、程序

```
data/                      .gitignore 整目錄
  tlayer/                  屬 nk1-tlayer:nk1；scope user 同 group、只讀（750 / 640）
    t.sqlite  manifest.yaml
  scopes/<scope_id>/       屬 nk1-<id>:nk1-<id>，700
    meta.yaml              scope_id／建立時間／schema_version／normalize_version／ngram_version／kb 快照 hash／registry 路徑
    c.sqlite
    registry.csv           過渡期文件登錄表：doc_id,version,status,title
    nk1.sock               unix socket，600
    audit.log              見 §7
```

- scope_id 格式：**放設定檔，U5（NK-Locus）回覆前 spec 不定內容**；程式只做「符合設定檔 regex」檢查。
- 管理命令 `nk1-scope`（init／sync-registry／retire／export）與生成程序分屬不同套件；生成程序不 import 管理套件。`init` 與 `retire` 需 root（建／停 user、chown、chattr），用 sudoers 白名單限定這兩個子命令。
- `retire <id>`：停程序 → 目錄打包加密交回客戶或銷毀（依合約）→ 刪 user。**建得出來必須刪得掉**，這條進驗收。
- 生成期 `c.sqlite` 以 `?mode=ro` 開，`PRAGMA busy_timeout=5000`；ingest／sync 以同 user 另一命令寫，`journal_mode=WAL`。
- 容器化時的對應：一 scope 一容器、UID 對應、volume 700；I-3 的失敗訊號從 PermissionError 改為 mount 不存在——測試寫成「以兩種訊號之一為過」。

## 2. c.sqlite schema

```sql
docs(doc_id TEXT PK, version TEXT, status TEXT CHECK(status IN('effective','superseded','draft')),
     title TEXT, sha256 TEXT, ingested_at TEXT, source_kind TEXT);
clauses(ref_id TEXT, version TEXT, doc_id TEXT, clause_no TEXT, ord INTEGER,
        text_raw TEXT, text_norm TEXT, ngrams TEXT,          -- ngrams＝normalize 後的 bigram+trigram 以空白分隔
        doc_offset_start INTEGER, doc_offset_end INTEGER,    -- 文件全文座標，名稱與驗證器的 offset_* 區分
        PRIMARY KEY(ref_id, version), FOREIGN KEY(doc_id) REFERENCES docs);
CREATE VIRTUAL TABLE clauses_fts USING fts5(ngrams, content='clauses', content_rowid='rowid', tokenize='unicode61');
```

- `ref_id`＝`<doc_id>#<clause_no>`，不含版本；`version` 為唯一權威；驗證器以 (ref_id, version) 聯合查。
- n-gram 切法：對 `text_norm` 取所有連續 2 字與 3 字（CJK 與英數同法；英數詞先以空白／標點切 token 再取 n-gram），去重，空白分隔。`ngram_version` 進 meta，改法即重建。
- 查詢：`normalize()` 後同法切 n-gram，組成 `MATCH` 查詢（AND），bm25 排序；query < 2 字元拒絕。
- status≠effective 進表、**進 FTS 但帶 status**，search 時過濾（不再靠「不進 FTS」）；export_kb 全輸出並帶 `status` 欄，讓驗證器能區分「作廢」與「不存在」（C6）。
- external-content FTS 的一致性：所有寫入在單一 transaction 內完成 `clauses` 寫入＋`INSERT INTO clauses_fts(clauses_fts) VALUES('rebuild')`；中途失敗整筆 rollback（D3、不足①）。語料幾千條，rebuild 秒級。

## 3. 登錄表同步

`nk1-scope sync-registry <id>`：讀 `registry.csv` → 更新 `docs.status` → 同 transaction 內 FTS rebuild → 更新 meta 快照 hash。**生成前必跑**；D5 靠這一步。

## 4. 呼叫協定與檢索 API

- 協定：unix socket、JSON Lines，每連線一請求一回應，程序單執行緒、同時一請求（併發上限＝1，v1 夠用；多使用者由呼叫端排隊）。請求 `{"op":"search"|"export_kb"|"snapshot_hash", ...}`。
- `search(query, k=20) -> list[Hit]`；`Hit={ref_id, version, kind("C"|"T-ref"), doc_id, clause_no, status, text_raw, text_norm, doc_offset_start, doc_offset_end, score}`。
- `export_kb(path, include_tlayer=True) -> sha256`：每行欄位＝契約 v1.1 `{ref_id, kind, version, clause, status, text_raw}`（`clause`←`clause_no`；不輸出 text_norm，驗證器重算）；序列化凍結：依 (kind, ref_id, version) 排序、`json.dumps(sort_keys=True, ensure_ascii=False, separators=(",",":"))`、每行 `\n`、無尾行；大小上限 64 MB，超過拒絕並要求分 scope。
- `snapshot_hash()`：sorted (ref_id, version) 的 `text_norm` 逐行 sha256。
- 三個 hash：`pack.kb_snapshot={C: snapshot_hash, T: manifest sha}`；驗證器記 kb.jsonl 檔案 sha。**序列化凍結後，第三者可由前兩者＋本 spec 重算**——這句只在凍結規則不變時成立，ngram／normalize 改版即失效，故三者都寫版本。
- offset 兩套：驗證器回填 `offset_start／offset_end`＝條內座標（維持 v1 已落檔欄名，spec 讓步）；內容包另存 `doc_offset_start＝clause.doc_offset_start＋offset_start`（及 end），供 NK-Locus 對版面。

## 5. Ingest

`nk1-ingest --doc <path> --doc-id --version --status --kind`（scope user 下執行）
①解析（v1：python-docx／pdfminer.six，離線 wheel 需對應目標機 OS／arch／Python，`--require-hashes`）→②依條號 regex 切條→③normalize→④切 n-gram→⑤單 transaction 寫 docs／clauses＋FTS rebuild→⑥更新 meta。同 doc_id 新版本：舊版 status→superseded（仍在表、仍在 FTS、search 過濾）。

## 6. 隔離不變量（測試）

- I-1（lint，輔助）：生成套件內不得出現 `scopes/` 後接 `*`／glob／listdir／walk／scandir／iterdir；**明知可繞，只當提醒**。
- I-2：兩 scope 各 ingest 不同合成語料；「B 獨有詞」由測試**自動產生**（B 的 n-gram 集合減 A 的，seed 固定隨機取 20），A 程序 search 命中 0。
- I-3（主要）：以 nk1-A 執行，open `data/scopes/B/` 任一檔 → PermissionError（或容器下 mount 不存在）。E1：Air2 不驗，落部署機。
- I-4：export_kb 只含 A＋T。
- I-5：scope user 對 tlayer/ 任何寫入拋錯。

## 7. 稽核日誌

`audit.log`：`who／when／scope／query sha256／pack_id`，不含正文。**append-only 由部署期 root 設**（Linux `chattr +a`；macOS `chflags sappnd`）；未設時 meta 標 `audit_append_only: false`，包內揭露。scope user 自設的旗標不算數（C5）。
